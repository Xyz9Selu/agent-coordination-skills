# 同伴 agent 递来的因果说法，不是你观测到的事实

[`SKILL.md`](SKILL.md)「同伴递来的因果说法」两条规则的来历。你要据以做不可逆动作、而手里的依据是转述时读这一页。

技能里已经教你提防两类东西：**信号正常但事情停滞**（停摆四信号在「跑长命令」「已完工」「被 resume」三种情况下
全读作健康），以及**信号异常但事情健康**（「已关闭」不等于做完、grill agent 长时间 `idle` 是正常的）。**第三类是
从同伴 agent 那里收到的因果说法**，它不是效率问题，是污染源：单 agent 里不核只是慢，多 agent 里不核就是把错误
接进管道。

两个不同的机制，别混着记：

- **传递不衰减（错误保值）** —— 一个错误说法经过一手不会变弱，措辞反而更肯定。人类协作里至少还有「你从哪儿
  听来的」这个本能，agent 之间没有，收到的东西默认就是事实。
- **每一手都是注入点（错误新增）** —— 错误不只是被转发，它可以在**任何一手被新造出来**。

2026-08-27 / 08-28 两天实际发生四次，**两个方向各两次**，这正是第二条的证据：

| 方向 | 说法 | 实际 |
|---|---|---|
| subagent → coordinator | 任务 X「前提已塌，建议关掉」 | 只塌了一半。描述里的问题段确实不成立，但候选做法段要的东西**不存在、是真活**，还带三个未决产品问题。照单接收就会关掉一件含真实需求的活，而且关得理由充分、无人复查 |
| subagent → coordinator | 「某个合并请求是 X 前提失效的原因」 | 实际是一个早得多的提交（引入一份 ADR），**比那个合并请求早两个月**。听起来完全合理，因为那个合并请求确实动过那一片 |
| coordinator → subagent | 「本周有五件活因为『待验收』状态标记而隐形」 | 实际 **1 件**。我把「因标记隐形」和「关闭后标记脏」两种失效归成了一类 |
| coordinator → subagent | 「某个提交漏掉了项目说明文件里的测试计数」 | 那个提交**明确豁免了**它们并写了理由。我看到「别处删了、这处还在」就推断成「教训没推广」，**而我没读提交正文** |

四次里**三次是被下游顶回来的**（下游去核了原始证据），一次是我自己回头核出来的。双方都不核，四次全都会落地。所以
下游不是转发管道，**它是唯一实际生效的检查点** —— 只在上游设防的规则会漏掉一半，还会让下游放松警惕。

**规则：**

> **任何要据以采取不可逆动作（关掉一件活、改状态标记、发牌、写进文档）的说法，如果它带数字或带因果，
> 必须回到原始证据核一遍** —— 提交正文、任务记录、实际代码，而不是转述。核不出来就在产出里标注来源和置信度，
> **不要抹平**。纯观察描述（「那个文件在这儿」）可以采信。

**比形式判据更好用的一条**（上面三个不成立的说法形状完全相同：叙事先成型、证据后补）：

> **当一个解释让你当下的叙事变得完整时，那正是最该去核的时刻。**

它靠**你自己的满足感**触发，而那个信号在错误发生的当下就是可感的 —— 不需要先识别出「这是一个因果说法」。上表
三条分别让「标记卫生是系统性问题」有了规模、让「预警起作用了」有了结局、让「同一个教训没被推广」有了因果。没有
一条是随机的错误。

口径提醒：一篇复盘文章收尾写的「三次里有两次」是**该文写作过程中**遇到的，上表四次是**那一轮盘面全部**。两组口径
不同，**分开放比合并强** —— 合并会让两边都不再可核。

## 用户口头说的「已合并」也要核（2026-09-17/18）

我按一句「某某 merged」把一件活关成了已完成，**没核**。实际合进去的是另一个交付物，用户说的那个仍未合并，主干上
它应该删掉的那个符号还在。这条与上面是同一把尺子——上面只写了同伴，但**人也会说错**，而且人说错时你更不会去查。

核一次的成本是两条命令：问工作流那个交付物的状态与合并时间（Q3），再直接看主干：

```bash
git show origin/main:<该交付物改过的文件> | grep -c "<它应该删掉的东西>"
```

第二条比第一条硬：交付物状态可能因为 squash/rebase 显示得含糊，而「那个符号在主干上还剩几个」不会骗人。

同类的另一个实例在 `herdr-agents` §7：我把「workspace 消失了」解释成「`worktree remove` 会连带关它」，其实是用户
手动关的——来源是我自己，不是同伴。
